| 旧数据迁移 | 默认只审计；冲突返回记录 ID，停止迁移；无冲突时添加名称键、回填并建立唯一约束；支持重跑，不改业务名称 |
| 前端适配 | 有会话时输入失焦调用名称预检查；无会话继续 mock；显示图片上传提示，增加客户端校验，没有新增字段或登录界面 |

白名单：脚本 `.py/.js/.sh/.bash/.ps1`，归档 `.zip/.whl/.gz/.tgz/.tar`，文档 `.md/.txt/.json/.csv/.pdf/.doc/.docx/.xls/.xlsx`，图片 `.png/.jpg/.jpeg`。本记录完成时采用单文件50MiB、合计500MiB，已废止；中间500MB方案也被老师后续要求替代。现行是单文件20MB（20,000,000字节）、每次最多5个直接上传，不设合计20MB限制。知识库展开100个实际资源工程上限单独保留；最新规则见v3方案。后续八项版还扩展了GIF/WebP/SVG。

图片位于 `<技术名>/assets/business-flow.png`。`SKILL.md` 保留“生成测试用例前，读取业务流程图”的统一说明，并生成相对链接。引擎不解码图片、不做 OCR/模型识别、不执行脚本、不安装或解压归档；扩展名检查不等于内容扫描或有效图像检测。

描述规则与代码对齐：名称前缀加执行指令首个非空行，合并空白并截断到 1024 字符；执行指令正文完整保留，不通过大模型概括。

## 迁移与交接

在后端仓库执行，本地 SQLite 默认只读审计：

```powershell
.\.venv\Scripts\python.exe -m examples.migrate_skill_names --sqlite output/skill-integration/integration.sqlite3
```

停技能写入、用数据库备份接口取得并验证完整备份且审计无冲突后应用（SQLite WAL 模式不能仅复制主文件）：

```powershell
.\.venv\Scripts\python.exe -m examples.migrate_skill_names --sqlite output/skill-integration/integration.sqlite3 --apply
```

团队配置数据库的只读审计入口为 `--configured-db`；本批没有调用它，没有读取或修改团队数据库。MySQL 实施分支已提供，实际迁移尚未验证。

正式旧库需要维护窗口：停止技能写入并备份 → 审计 → 团队处理重名/无效旧名称 → 核对既有 Aerich 历史及字段/唯一索引变更 → 回填名称键 → 验证 → 恢复服务。仓库启动包含自动 Aerich 逻辑，本脚本不更新 Aerich 历史；应选择经审核的 Aerich schema 变更后运行回填（工具能识别已存在字段和索引），或协调手工 schema 变更及迁移历史，避免重复添加字段。不能在仍有写入时仅补一列就上线；MySQL DDL 不能依赖事务完整回滚。

批量 ORM/SQL 修改名称或状态必须同步名称键；当前业务 API 使用模型保存路径。没有自动改名、删除旧数据或改动团队用户体系。
