## 本批完成什么

1. `SkillDeveloperForm` 明确接收 description/version，分别限制 1024/64 字符；缺失或仅空白在生成时返回对应 missing_fields，类型和长度错误返回 errors。继续禁止客户端指定创建者、技术名和服务器路径。
2. 适配器使用本次表单描述和版本，不自动生成描述、不截断、不补默认版本。首尾空白按已有合同清理，内部换行、空白、引号、冒号保留。
3. 构建服务仅从历史沿用技术名。修改版本不会继承旧版本；相同版本再次生成也有新的 build_id，旧定义与旧 ZIP 保持不变。数据库描述仍在现有事务中保存，资源失败会回滚本次名称和描述。
4. 图片归类补齐 GIF/WebP/SVG，大小写扩展名均进入 assets。所有图片原样保存，不解码、不执行 SVG、不做模型识别。
5. 新表单接口文案和 OpenAPI 摘要改为八项；multipart source/files 方式及旧标准生成接口不变。
6. 共用测试表单补齐描述和版本。旧的自动描述/默认版本/禁止新字段断言已替换，新增必填、边界、历史与图片场景。

没有新增数据库版本列、修改知识库 CRUD、执行脚本、调用模型、实现审批或调整登录页面。前端业务代码未改。

## 新手下一步怎么用

1. 使用已有平台会话取得 Token；解析引擎不单独增加登录页。
2. POST /skills/ 创建禁用记录，取得 skill_id。
3. 使用 [八项表单示例](../examples/skill-package/source-form-v3.json)，将 skill_id 替换成上一步 ID；把 JSON 字符串放入 multipart 的 source，文件放入重复的 files 字段。
4. POST /skills/form/builds，检查响应 status；保存 build_id。
5. GET /skills/{skill_id}/builds/{build_id}，用 source/files 展示只读约束；调试页不能用后来修改的草稿替代旧构建定义。
6. GET /skills/{skill_id}/builds/{build_id}/download，检查完整 ZIP。
