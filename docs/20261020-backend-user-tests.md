## 3. 发现的问题怎样修复

### 失败后的相同文件重传被跳过

原来只根据“新旧哈希相同”跳过处理，没有区分上一次已经完成还是失败。现在已完成且内容相同时保留索引；失败时使用本次实际上传文件重新处理。已完成文件重传也会更新原文件存储，修复缺失或损坏的字节。

### 批量替换、改名被数据库中间状态误判重复

原来逐个更新内容哈希，第一份新内容可能暂时与第二份旧内容冲突，即使最终集合合法也会失败。

现在先检查本次保存后的最终文件集合，明确找出真实重复；再在同一个数据库事务中释放变更/移除文档的旧哈希，写入最终结果。失败整体回滚，没有取消数据库唯一约束。

### 附件重复错误定位到名称

原来数据库冲突统一报“知识库名称或文档内容重复”，前端可能错误标红名称。现在提前给出具体重复文件名，并定位 `files[index]`。

### 总状态提前失败，导致页面可能停止轮询

现在只要还有文档或清理任务处理中，总状态就保持 processing；全部结束后再汇总失败或完成。每个文档仍分别显示自己的状态。

### 预校验、表单校验、编辑接口反馈不一致

空白名称不再显示“可用”。Skill/知识库表单的必填、长度、选项等常见提示统一为中文，返回字段位置。编辑器和挂载等请求的模型校验也返回统一 `data.errors`，不再直接把英文校验详情交给用户。

### 旧上传入口漏掉空文件校验

校验放到公共包生成器中，新的表单入口和历史入口都不能生成包含空资源的包。

## 4. 是否符合用户使用习惯

本轮评价的是后端能否支持常用操作，不是对页面的可用性或真实用户测试作最终结论。

| 使用习惯 | 本轮后端结果 |
| --- | --- |
| 用户不应该手动维护版本、作者和服务器路径 | 由服务器决定；版本来自成功保存结果，身份来自统一登录 |
| 失败了重新上传同一文件，应能恢复 | 已验证 |
| 内容没变，不应该每次重复花时间向量化 | 已验证；相同内容重传不重建已完成索引 |
| 批量替换、移除后改名，应该按最终选择生效 | 已验证 |
| 错误应该指出具体字段或文件 | 已验证常见必填、长度、空文件、重复附件和版本冲突 |
| 保存失败不能弄丢原来的内容 | 已验证旧构建、旧版本、历史和原有效索引保留 |
| 处理没有全部结束，不能提前显示最终结果 | 已验证状态汇总 |
| 文档处理中也应允许改说明等元数据 | 已验证；不允许同时替换处理中的实际文档 |
| 看得到公开知识库，不等于能改别人的内容 | 已验证读写权限分离 |
| 多窗口编辑不能悄悄覆盖新版本 | 已验证携带 expected_version/expected_generation 时返回冲突 |

仍需在前端对话中验收这些交互，不能仅凭接口通过就打勾：

1. 一次点击保存即可完成后台请求；请求中禁用重复提交，不要求用户手动创建 ID。
2. 首次创建技能记录后若生成失败，应保留返回的 backendSkillId 以便重试，不重复创建同名记录。
3. 字段错误就近显示，保留用户已填写内容；版本冲突不能直接自动刷新并清空编辑器。
4. 知识库管理页空搜索显示可见列表；挂载选择器未输入关键词时按产品要求显示搜索提示。
5. 处理中可见状态及每个文件的结果，完成后刷新；失败时提供重试或重新上传入口。
6. 原文件/ZIP 下载、长文件名、移除文件和取消弹窗在真实页面上操作是否顺手。
7. 页面使用平台真实会话和服务器 can_edit，不用演示用户下拉框模拟服务器权限。

本轮只读查看了前端适配代码，未做修改；当前真实 API 接入仍须在前端对话中继续，不能把页面模拟行为算进这次验收。

| 知识库查看 | 名称模糊搜索、分页、详情、文件列表、原文件下载、解析 Markdown 预览、分块查看 |

| 知识库版本 | 自动版本、变更摘要、创建/修改历史、并发版本检查 |
| 知识库恢复 | 失败重试、相同文件重传恢复、中断任务显式恢复、保留旧索引、清理中断写入的向量 |
| 知识库权限与挂载 | 本人私有/全平台公开；只有创建者可编辑；公开资料可挂载到本人 Skill；实际原文件进入完整包 |
