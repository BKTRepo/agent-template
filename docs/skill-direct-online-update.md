# Skill 解析引擎：取消审批后的范围与当前操作

更新时间：2026-10-14。依据：用户说明产品改为面向测试经理，取消审批；新版原型 `(1)(3).html`；当前前端已改为自测通过后点击“上线”。用户明确本次仍只负责 Skill 解析引擎，不开发真实上线接口。

## 1. 本次确认结果

当前后端没有审批模型、提交/查询审批路由或“待审批”状态；无需删除审批业务代码。八项表单、文件归类、生成、保存、查询、下载不变。单文件20,000,000字节、每次最多5个直接上传文件等现有规则继续使用。

本次实际更新设计和交接资料，取消后续审批接入要求。没有新增运行器、上线接口、测试经理角色，也没有把生成成功改成自动启用。`SkillPackageBuilder.build` 中临时目录的“发布”是完整文件目录就绪，不是业务上架。

## 2. 当前正确流程

```text
填写表单、上传资源
    ↓
解析引擎生成 Skill 包（本模块已实现）
    ↓
指定构建进行真实自测（运行服务后续接入）
    ↓
自测通过后点击上线（上线服务后续接入）
```

不再有审批申请、审批记录、审批按钮、审批通过才能上线的要求。新版前端的 `publishSkill`、`applyPublication` 是直接上线接线点，目前对演示数据提供模拟处理，对真实记录明确提示未接入。

## 3. 你现在可以完成什么

1. 核对八项生成合同与前端字段，保持已有生成接口。
2. 交付可生成 SKILL.md 的无附件样例，以及含文档/图片/脚本的完整 ZIP 样例。
3. 用现有测试说明名称、资源、权限、历史及下载已经覆盖；上一批完整后端162项通过。这次只改资料，没有新业务代码，不重复运行无变化的全部测试。
4. 更新方案/手册，明确后续真实自测和上线尚未接入；本周解析引擎可以先交接，不等其他模块完成。
5. 继续学习表单转换与 `_render_skill`，能解释输入字段如何变成 YAML、正文和相对资源链接。

现在不需要自行开发 Agent 看图、脚本执行、依赖动态加载，也不需要先写一套模拟上线后端。

## 4. 后续联调只需保留的交接信息

解析引擎已经提供：

| 信息/接口 | 用途 |
|---|---|
| skill_id | 指定哪条技能记录 |
| build_id | 指定本次生成快照，不能用后来草稿替代 |
| GET /skills/{skill_id}/builds/{build_id} | 读取并校验 source、files、package_sha256 和可信目录 |
| GET /skills/{skill_id}/builds/{build_id}/download | 下载对应完整 ZIP |
| workspace_dir/skill_directory | 服务端运行器加载位置；跨服务器需约定共享存储或可信包传输 |

赵的真实自测服务完成后，双方再确定执行接口、文件输入、日志/结果、真实自测结果ID。上线接口由团队明确负责人，服务器需要校验自测结果属于当前用户和同一skill_id/build_id，并且成功，再记录生效构建和上线状态。**不能把客户端的passed、模拟debugId或is_enabled更新直接当真实自测证明。**

这是未来接入要求，不是当前新增的HTTP路由。当前已有基础Skill CRUD不包含这套自测结果与发布校验。

## 5. 样例和既有数据注意事项

本地生成器演示使用演示身份、直接调用builder，没有创建数据库技能记录，所以样例里的ID不能直接拿来调用真实HTTP接口。先POST /skills/取得真实ID，再POST /skills/form/builds取得真实build_id。

以前验收脚本创建的测试技能已软删除；其ZIP仍可展示，但正式联调应重新创建测试记录。

旧前端“待审批”记录由前端schema v2迁移：移除approval，有构建变调试中、无构建变草稿，并清除旧通过结果。它们不能因为取消审批就自动上线。后端没有对应审批表需要迁移；不要删除Skill记录或历史包。

## 6. 现有单文件单位差异

前端已改为20MiB（20×1024×1024=20,971,520字节）/5个，后端按用户此前确认采用20MB（20,000,000字节）/5个。数量一致，单位还有971,520字节差异。后续前端需与后端统一，或团队明确采用MiB后再一起调整；本次没有借取消审批去改变已经确认的大小规则，也没有修改前端。
